# Isolated kernel backport checks

These scripts build the current source for an ARM64 QEMU `virt` machine and
check its reported kernel release against the release generated by Kbuild. The
guest also checks that its disposable virtio block device is present. The
default runner uses a gzip initramfs and an unformatted scratch image. Optional
cases exercise Zstd startup unpacking and F2FS through guest userspace. See
[validation.md](validation.md) for actual results and artifact hashes.

The RMX1901 build and the QEMU build use the same source tree with different
configurations. Neither procedure flashes a device, opens a physical block
device, or modifies an existing filesystem. QEMU cannot establish Qualcomm ICE
hardware compatibility. Both encryption paths remain in scope under
[the approved spec](https://github.com/Lcryolite/kernel_realme_sdm710/issues/14);
hardware runtime behavior remains `unverified` without suitable hardware tests.

**Inputs and toolchain**

Use a complete `stock-next` checkout with its pinned BakaSU submodule present.
Keep generated files in separate output directories; generated headers in the
source tree can interfere with an `O=` build. Record the source commit, any
working-tree patch, and `git submodule status` alongside each result.

The available compiler used for this baseline is Neutron Clang `24.0.0git`,
LLVM revision `17efc66a340e35ae03a18e34e7f267832fff7940`, at
`/home/lknife/Projects/rmx1901_xnu/out/toolchains/neutron-30072026/bin`.
Its matching LLD reports the same revision. The existing toolchain's original
archive checksum was not available, so this identifies the executable's reported
revision rather than verifying an upstream toolchain archive.

Despite its filename, `build-clang22.sh` permits this compiler with
`REQUIRE_CLANG_MAJOR=24`. It needs the LLVM tools named in the script and GNU
cross binutils for both AArch64 and ARM32. On this host the prefixes are
`/usr/bin/aarch64-linux-gnu-` and `/usr/bin/arm-none-eabi-`. With that ARM32
binutils prefix, keep `CLANG_TRIPLE_ARM32=arm-linux-gnueabi-`: the ARM32 vDSO
must be linked as a Linux shared object. A native `arm-linux-gnueabi-` binutils
installation can be used instead.

The host also needs Bash, GNU make, a C/C++ host compiler, binutils, Perl, bc,
flex, bison, gzip, zstd, and coreutils. The full suite uses Python 3.11+ and host
LZ4/Zstd shared libraries for independent fixture preparation. Install
the development headers required by the selected kernel configuration, including
OpenSSL/libelf where enabled. This directory does not install host packages.

The examples below use Bash and an empty build environment. Adjust the first
three paths and cross prefixes for another machine.
The timestamp and build identity are fixed for subsequent reproductions; these
settings do not assert that byte-for-byte reproducibility has already been
tested.

```bash
set -euo pipefail
workspace=/home/lknife/Projects/kernel_rmx1901
repo="$workspace/kernel_realme_sdm710_full"
llvm_bin=/home/lknife/Projects/rmx1901_xnu/out/toolchains/neutron-30072026/bin
test_dir="$repo/tools/testing/selftests/kernel_backport"
build_tmp="$workspace/build/tmp"
mkdir -p "$build_tmp"
build_timestamp=$(git -C "$repo" show -s --format=%cD HEAD)

build_env=(env -i
    USER=builder LOGNAME=builder
    PATH="$llvm_bin:/usr/bin:/bin" LC_ALL=C TZ=UTC TMPDIR="$build_tmp"
    KBUILD_BUILD_USER=builder KBUILD_BUILD_HOST=isolated
    KBUILD_BUILD_TIMESTAMP="$build_timestamp" KBUILD_BUILD_VERSION=1
    CCACHE_DISABLE=1
    CROSS_COMPILE=/usr/bin/aarch64-linux-gnu-
    CROSS_COMPILE_ARM32=/usr/bin/arm-none-eabi-
    CLANG_TRIPLE_ARM32=arm-linux-gnueabi-
    JOBS=4)
```

**Build the RMX1901 configuration**

```bash
"${build_env[@]}" \
    LLVM_BIN="$llvm_bin" HOST_BIN=/usr/bin GNU_BIN=/usr/bin \
    REQUIRE_CLANG_MAJOR=24 KERNEL_DEFCONFIG=RMX1901_defconfig \
    OUT_DIR="$workspace/build/rmx1901" BUILD_DTBS=1 \
    ENABLE_THINLTO=0 ENABLE_POLLY=0 ENABLE_LLVM_TUNING=0 ENABLE_O3=0 \
    bash "$repo/build-clang22.sh" \
    2>&1 | tee "$workspace/build/rmx1901-build.log"
```

This builds `Image.gz`, `vmlinux`, and the four device-tree targets selected by
the script. The configuration retains the device platform, appended-DTB support,
ramoops, and the existing device features. ThinLTO, Polly, CPU tuning, and the
additional `-O3` option are explicitly disabled for this baseline; enabling the
CI optimization profile is a separate build input. Keep `Image.gz` as the device
kernel payload when adding support for Zstd-compressed initramfs archives.

**Build the isolated test configuration**

```bash
"${build_env[@]}" bash "$test_dir/build.sh" "$workspace/build/qemu" \
    2>&1 | tee "$workspace/build/qemu-build.log"
```

`build.sh` applies [qemu.config](qemu.config) through `KCONFIG_ALLCONFIG` and
`allnoconfig`, then builds an uncompressed ARM64 `Image`. Inspect the generated
`.config`, since Kconfig resolves the fragment's dependencies. PL011 supplies
the serial console, virtio-mmio and virtio-blk supply the scratch disk, and
initramfs/ELF support plus procfs, sysfs, and devtmpfs supply the test userspace.
The `/init` shell script also requires script binary-format support.

The fragment retains `SCHED_WALT`, `NO_HZ_IDLE`, `SUSPEND`, `CGROUPS`,
`CGROUP_SCHED`, and `FAIR_GROUP_SCHED` because this vendor tree still references
those scheduler and power-management interfaces in a reduced configuration.
They are build prerequisites for this tree, not claims of hardware coverage.
It also enables `F2FS_CHECK_FS` and `F2FS_IO_TRACE` (with its function-tracing
dependencies). Tracing stores PID values in ordinary pages' private fields;
the suite therefore checks that compressed temporary pages use a distinct
ownership marker before interpreting that field as a context pointer.

Three platform prerequisites allow this source to run outside RMX1901:

- `drivers/misc/Makefile` builds `schedx.o` only with
  `CONFIG_PRODUCT_REALME_SDM710`, matching the vendor scheduler interfaces it
  uses.
- `arch/arm64/kernel/head.S` limits both the call to
  `rmxdiag_early_ramoops_mark` and its implementation to that device config.
  Its physical write to `0xb7f40000` is outside the 512 MiB QEMU RAM range
  `0x40000000` through `0x5fffffff`, causing an exception before early console
  output without the guard.
- `init/main.c:rmxdiag_ramoops_checkpoint` returns immediately when
  `CONFIG_PRODUCT_REALME_SDM710` is disabled. Guarding the assembly entry marker
  alone is insufficient because these later checkpoints use the same
  device-specific physical memory region.

These conditions preserve the existing RMX1901 paths while excluding device
memory accesses from the generic test kernel.

**Run the isolated guest**

Use a trusted, statically linked **AArch64** BusyBox with `sh`, `mount`, `cat`,
`uname`, and `poweroff` applets. The repository's `AnyKernel3/tools/busybox` is an
ARM32 Android binary and is not the userspace input for this test. Check a
replacement with `file` and `readelf -l`; it must not require a dynamic loader.
On an x86_64 host, use an AArch64 emulator for any execution probe.

```bash
qemu_root="$workspace/tools/qemu"
busybox="$workspace/tools/busybox-aarch64/bin/busybox.static"

env -i PATH=/usr/bin:/bin LC_ALL=C \
    TMPDIR="$build_tmp" LD_LIBRARY_PATH="$qemu_root/usr/lib" \
    QEMU="$qemu_root/usr/bin/qemu-system-aarch64" \
    QEMU_DATA_DIR="$qemu_root/usr/share/qemu" BUSYBOX="$busybox" \
    bash "$test_dir/run.sh" "$workspace/build/qemu" \
    "$workspace/build/qemu-run.log"
```

For a system-provided QEMU, set `QEMU` to its executable and `QEMU_DATA_DIR` to
its data directory; omit the local `LD_LIBRARY_PATH`. Extracted host packages
depend on the host's shared-library ABI, so use native packages on a different
distribution rather than assuming the local package tree is self-contained.

The runner creates a temporary gzip initramfs and 128 MiB raw scratch file,
uses TCG with two Cortex-A57 CPUs, 512 MiB RAM and GICv2, and disables networking.
It boots with
`earlycon=pl011,0x09000000 console=ttyAMA0 rdinit=/init panic=-1` and enforces a
90-second timeout. The guest powers off after checking its release and disk;
the runner removes its temporary files and retains the requested serial log.

A passing invocation must return zero and contain `KERNEL_BACKPORT_PASS:` with
the exact release from `include/config/kernel.release`. A timeout, a nonzero
QEMU exit, a `KERNEL_BACKPORT_FAIL:` marker, or a missing pass marker is a failed
check. A startup banner or successful compilation alone does not establish a
passing guest result.

**Prepare an independent F2FS compression fixture**

[make-f2fs-fixture.sh](make-f2fs-fixture.sh) creates a new directory containing a
256 MiB F2FS image with `extra_attr,compression`, a known payload with a partial
tail, its expected SHA256, and tool logs. It uses `sload.f2fs` with LZ4 and
`-L 2` to populate compressed data independently of the kernel under test. The
destination must not already exist.

```bash
f2fs_root="$workspace/tools/f2fs"
env -i PATH=/usr/bin:/bin LC_ALL=C \
    LD_LIBRARY_PATH="$f2fs_root/usr/lib" \
    MKFS_F2FS="$f2fs_root/usr/bin/mkfs.f2fs" \
    SLOAD_F2FS="$f2fs_root/usr/bin/sload.f2fs" \
    bash "$test_dir/make-f2fs-fixture.sh" \
    "$workspace/build/f2fs-lz4-fixture"
```

Set `F2FS_FIXTURE` to this directory when running `run.sh`. The guest identifies
each disk by its virtio serial number, independently of device enumeration
order. The default `F2FS_MODE=read` mounts the source image read-only and checks
the payload across a full unmount/mount. Mutation tests use private image copies.

For encryption fixtures, add `F2FS_ENCRYPTION=1` to the generator environment;
this enables `encrypt` only on the newly created disposable image. The generator
also produces a deterministic 1 MiB incompressible input for lifecycle tests.
Upstream sload supports LZ4 fixture creation; it does not provide a Zstd fixture
encoder. [make-zstd-fixture.py](make-zstd-fixture.py) validates the known LZ4
fixture, independently encodes its six clusters with host libzstd, and updates
the algorithm byte with native `inject.f2fs`. It preserves the standard layout
and writes an adjacent JSON provenance record. This is a transformed upstream
format fixture, not a native sload Zstd volume. The guest must still read it
successfully. Zstd write tests separately exercise the kernel encoder.

| Environment | Effect |
| --- | --- |
| `INITRAMFS_COMPRESSION=zstd` | Boot a Zstd-compressed initramfs; default is gzip. |
| `INITRAMFS_FAULT=bad-header` or `truncated` | Require controlled Zstd input rejection, not a timeout. |
| `F2FS_MODE=read` | Read the independently generated LZ4 fixture. |
| `F2FS_IMAGE`, `F2FS_READ_FILE` | Override the input image and payload name; the default name is `payload`. |
| `F2FS_MODE=reject` | Require read errors from an image with deliberately invalid metadata. |
| `F2FS_MODE=corrupt`, `F2FS_CLUSTER_BLOCK`, `F2FS_BAD_CLEN` | Modify the length at an inspected compressed storage block in a private copy and require read errors. |
| `F2FS_PAYLOAD_FAULT=truncated` or `bad-magic` | In corrupt mode, shorten a valid frame by one byte or damage its magic (Zstd), reaching the filesystem decoder rather than only outer length checks. |
| `F2FS_MODE=write` | Explicit file and directory selection, ordinary peer, sync, and unmount/mount checks. |
| `F2FS_MODE=lifecycle` | Overwrite, append, truncate, links, deletion, and repeated allocation/reuse checks. |
| `F2FS_MODE=encrypted`, `FSCRYPT_TEST` | Software fscrypt v1 key lifecycle and file checks using the static helper. |
| `F2FS_MODE=encrypted-gc`, `F2FS_GC_START` | Use a prior encrypted result, close its data segment, force GC, and remount; the host must separately verify selected storage relocation. |
| `F2FS_MODE=checkpoint-write` or `orphan-write` | Sync compressed data and power off without unmounting; the latter holds an unlinked file open. |
| `F2FS_MODE=checkpoint-read` | Reboot a dirty output image, verify persisted files, and check orphan removal. |
| `F2FS_CODEC=lz4` or `zstd` | Select the codec for new guest files; default is LZ4. |
| `F2FS_RESULT_IMAGE` | Required new output path for mutation/recovery cases; retained on success or failure for offline inspection. |
| `QEMU_TIMEOUT` | Timeout in seconds; default 90. Use 600 for allocation/reuse tests. |

Build the ARM64 helpers against a static libc compatible with Linux 4.9. The
verified local Alpine musl sysroot contains the startup objects, libc archive,
and Linux userspace headers. Android NDK r30's Bionic libc aborts on this kernel
because it requires `MADV_WIPEONFORK`; selecting API 21 does not fix that static
runtime dependency. Its compiler-rt archive can still supply freestanding
arithmetic routines without linking Bionic.

```bash
env -i PATH="$llvm_bin:/usr/bin:/bin" LC_ALL=C \
    MUSL_SYSROOT="$workspace/tools/musl-aarch64" \
    COMPILER_RT_BUILTINS=/opt/android-ndk/toolchains/llvm/prebuilt/linux-x86_64/lib/clang/21/lib/linux/libclang_rt.builtins-aarch64-android.a \
    bash "$test_dir/build-userspace.sh" "$workspace/build/helpers"
```

Set `FSCRYPT_TEST` to `build/helpers/fscrypt-test` and `F2FS_GC` to
`build/helpers/f2fs-gc`. The encryption helper uses deliberately public test
keys inside a new guest session keyring. Tests fully unmount between key changes
to evict inode-cached v1 keys. Do not run its key commands on the host.

The lifecycle test requests synchronous GC on the first compressed storage
segment of the inspected fixture, after enough compressed data closes that
segment. It requires successful GC data-I/O counters and checks surviving
contents; offline inspection can additionally confirm that the original
compressed blocks changed physical addresses. An ioctl success alone is not
treated as proof of movement. Set `F2FS_DATA_FLUSH=1` for the corresponding
mount-option regression.

**Run the complete isolated matrix**

[suite.sh](suite.sh) runs the startup cases, both filesystem codecs, length
and metadata rejection, selection/inheritance, updates and allocation reuse,
measured GC, `data_flush`, checkpoint/orphan recovery across two boots, and
software encryption. It also compares each selected encrypted file's compressed
storage slots before and after GC: the selected blocks must move outside the
target segment, their stored ciphertext must remain byte-for-byte identical,
and guest reads must still recover the expected plaintext. A counter alone
does not establish that the selected file moved.
It invokes native `fsck.f2fs --dry-run -f` on the mutation
outputs and retains logs and images for independent inspection. It stops on
the first failure; `SUITE_PASS` requires every case to return successfully.
The final results directory must not exist. The fixture must have been created
with `F2FS_ENCRYPTION=1`.

```bash
env -i PATH=/usr/bin:/bin LC_ALL=C \
    LD_LIBRARY_PATH="$qemu_root/usr/lib" \
    QEMU="$qemu_root/usr/bin/qemu-system-aarch64" \
    QEMU_DATA_DIR="$qemu_root/usr/share/qemu" BUSYBOX="$busybox" \
    F2FS_FIXTURE="$workspace/build/f2fs-lz4-all-fixture" \
    F2FS_LD_LIBRARY_PATH="$f2fs_root/usr/lib" \
    DUMP_F2FS="$f2fs_root/usr/bin/dump.f2fs" \
    INJECT_F2FS="$f2fs_root/usr/bin/inject.f2fs" \
    FSCK_F2FS="$f2fs_root/usr/bin/fsck.f2fs" \
    FSCRYPT_TEST="$workspace/build/helpers/fscrypt-test" \
    F2FS_GC="$workspace/build/helpers/f2fs-gc" \
    bash "$test_dir/suite.sh" "$workspace/build/qemu" \
    "$workspace/build/final-suite"
```

The mutation cases use copies, and negative cases deliberately leave damaged
images in the new results directory. Do not run filesystem repair over these
inputs and then present the repaired result as a passing rejection test.
The GC range and corruption offsets refer to the fixed fixture layout; the
Zstd conversion validates that layout before the suite runs.

If an incremental build changes from decoder-only Zstd to both codecs, this
tree's existing response-file Kbuild rule can retain removed dependencies in
`lib/zstd/zstd_decompress.o`. A duplicate-symbol failure in that situation needs
a fresh output directory or removal of that generated archive before rebuilding.
The `lib/zstd/Makefile` already excludes shared objects from the decoder when
both codecs are built in. Do not suppress the duplicate-symbol diagnostics.
